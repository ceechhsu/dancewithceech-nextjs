# BeatFirst Leaderboard Implementation Plan

> **For agentic workers:** Use subagent-driven-development for the bounded backend task and requesting-code-review for specification and quality review. Parent owns UI integration, browser verification, migration and release. Steps use checkbox syntax.

**Goal:** Publish an all-time Top 10 per BeatFirst level with opt-in public names and retained personal progress.

**Architecture:** Query personal bests from the existing server-scored attempts table, joined only to explicitly listed player profiles. Keep database access server-only with RLS, restricted grants, and an invoker RPC. A public Next.js GET returns sanitized rankings plus the current account's own profile; verified-account POST changes only that profile. A separate client widget below the game displays results without changing the timing engine.

**Tech Stack:** Existing Next.js/React/NextAuth, Supabase PostgreSQL, node:test and PGlite; Vercel staged production and promotion.

## Task 1 — Backend, migration, behavior tests (bounded implementer)

Files: new `src/lib/beatfirst-leaderboard-service.ts`, `src/lib/beatfirst-leaderboard-store.ts`, `src/components/beatfirst-preview/leaderboard-model.ts`, `src/app/api/beatfirst/leaderboard/route.ts`, CLI-generated migration, and `tests/beatfirst-leaderboard*.test.ts`.

- [ ] Write failing tests for per-level best selection, duplicate attempts/player exclusion, shared ranks, stable ties, exact ten-row cutoff, hidden/unlisted profiles, old bests appearing after opt-in, scores changing after additional saved rounds, name change/hide, case-insensitive name conflicts, anonymous viewing, auth/owner/origin/body validation and private-field stripping. Use PGlite against the real migration for SQL behavior/permissions, and dependency-injected service handlers for HTTP boundaries. Do not test only source strings or mocked query chains.
- [ ] Generate migration with `supabase migration new beatfirst_leaderboard`. Add `beatfirst_leaderboard_profiles(user_id text primary key, display_name text not null, listed boolean not null default true)` with normalized trimmed names (3–20 characters, letters/numbers/spaces/dot/underscore/hyphen; no email/@/HTML/control characters), a case-insensitive unique name index, RLS, and grants only to service_role for select/insert/update. No direct browser-role access and no public account identifiers. No default profiles/backfill.
- [ ] Add a supporting attempts index and service-role-only invoker SQL function `beatfirst_level_top_ten(p_level_id integer)` returning internal `{user_id,display_name,score,rank}`. Select each listed player's best attempt for this level using score descending, saved_at ascending, attempt_id ascending; then rank by score alone, order ties by saved_at/user_id, and limit 10. Use fully-qualified table names/fixed search_path and revoke function EXECUTE from PUBLIC/anon/authenticated. Do not alter the attempts writer or existing scoring.
- [ ] Shared client types: `LeaderboardProfile = {displayName:string;listed:boolean}`, `LeaderboardEntry = {rank:number;displayName:string;score:number;isYou:boolean}`, `LeaderboardData = {levelId:number;entries:LeaderboardEntry[];profile:LeaderboardProfile|null}`. Export a name normalizer/validator and level parser; both server/client can consume without server imports.
- [ ] `GET /api/beatfirst/leaderboard?level=1` validates an integer level 1–18. Anyone can read; when a verified session exists, return its own profile and mark matching entries isYou. Entries expose only rank/displayName/score/isYou. Optional `X-BeatFirst-Owner` mismatch returns 409. Private no-store response (includes own profile), 400 invalid level, 503 temporary failures.
- [ ] `POST` same route, body `{displayName,listed}` only: require verified Google session, exact `X-BeatFirst-Owner`, same Origin, application/json and streamed bounded body (4 KiB). Derive identity from session, never body. Normalize name, require boolean listed, conflict 409 for taken case-insensitive name, return `{profile}`. No score/level/other-user updates. Store uses the existing paired database configuration and server-only Supabase client. Errors use human-readable generic messages. Profile update must not touch saved attempts.
- [ ] Run backend tests; hand off files and evidence without migration application, source commit or deployment. Parent runs specification then quality reviews alongside integrated UI review.

Use semantic table or ordered list with clear labels; 44px controls and no phone overflow.
- [ ] Guest CTA signs in using existing progress.login. Signed-in account without profile sees name input and explicit `Join leaderboard` with copy that saved best scores and name become public. Existing profile can edit/save name or hide scores; hidden profile can rejoin. No Google name auto-fill or automatic enrollment. Inputs handle validation/conflict/error and clear on account change. Disable mutations during play or while auth/loading is uncertain.

Expose an optional onLeaderboard callback in ClapGame or a parent completed-round state. Abort/ignore stale requests on level/account changes, bound timeout, prevent stale owner/profile leakage and duplicate submission. Failures never disable game.
